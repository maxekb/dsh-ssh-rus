# AGENTS.md — dsh-ssh-rus

Плагин DSH: удалённые SSH-операции для веб-GUI (менеджер хостов, веб-терминал, передача файлов,
туннели, параллельное выполнение, инструменты агента). Форк `@linxin666/dsh-ssh` 0.4.2
(Apache-2.0) с русской локализацией, без телеметрии и с самостоятельной сборкой.

## Идентичность (не разъезжать!)

Одна и та же строка должна совпадать во всех местах, иначе панель или маршруты отвалятся:

| Что | Где | Значение |
|---|---|---|
| Имя пакета, строка бандла | `package.json: name`, `cordis.patch.yml: name` | `dsh-ssh-rus` |
| Ключ монтирования | `src/index.ts: mountOnce(...)` | `dsh-ssh-rus` |
| Префикс API | `src/protocol.ts: SSH_API_BASE` (используют обе половины) | `/api/dsh-ssh-rus` |
| Namespace локали | `src/client/index.ts: NS` + `LocaleNamespaceMap` в том же файле | `dsh-ssh-rus` |
| Ключи шины | `src/mount-once.ts`, `src/client/body-mutations.ts` | `Symbol.for('dsh-ssh-rus.*')` |
| id клиентского бандла | задаётся пресетом сборки: `tsdown.config.ts` → `clientBundle('dsh-ssh-rus', …)` | `dsh-ssh-rus` |

`SETTINGS_NS` в `src/client/index.ts` **остаётся `'dsh-ssh'`** — это адрес семейной поверхности
настроек апстрима, к идентичности не относится; менять без нужды не следует.

## Сборка и проверки

```sh
pnpm install          # зависимости ставятся локально, чужой монорепозиторий не нужен
pnpm run typecheck    # строгие словари: пропущенный ключ ru — ошибка
pnpm run build        # tsc (lib/types) + tsdown (lib/index.js, lib/client.js)
pnpm exec vitest run tests/locales-runtime.spec.ts
```

После сборки проверяйте отсутствие следов апстрима в артефактах:
`Select-String -Path lib\*.js -Pattern '@linxin666'` должен давать ноль.

## Локализация

`zh` — источник ключей (`src/client/locales.ts`); `en` и `ru` (`src/client/locales.ru.ts`)
типизированы как `Record<SshKey, string>`, поэтому пропустить ключ нельзя. Новую строку
добавляем во все три словаря; интерфейс берёт язык из сервиса локали (`ctx.locale.register`).

## Модель безопасности (не ослаблять)

- Пароли и парольные фразы — в открытом виде в `$DSH_HOME/dsh-ssh.json` (0700/0600). Это
  выбранная модель доверия; не шифровать «для галочки» и не логировать.
- `ssh_upload` / `ssh_download` пишут на локальной машине с правами процесса хоста; маршруты
  только loopback; туннели слушают только `127.0.0.1`.
- `ProxyCommand` исполняется процессом хоста; агент не может создавать и менять хосты.
- Вывод команд отдаётся без маскирования; переподключение может повторить неидемпотентную
  команду. Это документируется, а не «исправляется» молча.
- Телеметрии в этом форке нет и быть не должно: никаких сетевых «heartbeat» с именем пакета.
