# dsh-ssh-rus

Удалённые SSH-операции для веб-GUI **DeepSeek Harness (DSH)**: менеджер хостов, веб-терминал,
передача файлов, проброс портов, параллельное выполнение команд по группе хостов и инструменты
для агента. Русский интерфейс, без отправки данных наружу.

Это **форк** плагина `@linxin666/dsh-ssh` 0.4.2 (Apache-2.0, автор — zhu1090093659,
[github.com/zhu1090093659/dsh-web](https://github.com/zhu1090093659/dsh-web)), переработанный
под самостоятельную сборку и сопровождение. Не связан с автором апстрима и не одобрен им.

English version: [README.en.md](./README.en.md).

## Чем отличается от апстрима

| Изменение | Зачем |
|---|---|
| Русская локализация (`src/client/locales.ru.ts`, все ключи; тип `Record<SshKey, string>` не даёт пропустить ключ) | русскоязычным пользователям |
| **Удалена телеметрия** — файла `src/client/telemetry.ts` больше нет | апстрим отправлял ежедневный «heartbeat» с именем пакета на свой endpoint |
| Сборка самостоятельная: пресет сборки лежит внутри (`shared/tsdown.client.ts`, `shared/web-platform.ts`, добавлен `lightningcss`) | пакет собирается «из коробки», без чужого монорепозитория |
| Своя идентичность: пакет и строка бандла `dsh-ssh-rus`, ключ монтирования, префикс API `/api/dsh-ssh-rus`, namespace локали, свои ключи шины вместо `dsh-web.*` | модуль не смешивается с семейством плагинов апстрима |
| Подсказка агенту (`SSH_GUIDANCE`) переписана по-русски | агент читает её как инструкцию к этому плагину |

## Установка

```sh
pnpm dsh plugin --profile <профиль> add <путь-к-тарболу-или-каталогу>
```

Строку бандла пакет объявляет сам (`dsh.bundle.patch` в `package.json`). Если профиль её не
подхватил — добавьте `dsh-ssh-rus` в `dsh.profile.bundles` файла профиля и перезапустите DSH.

## Конфигурация

Хосты: `$DSH_HOME/dsh-ssh.json` (по умолчанию `~/.dsh/dsh-ssh.json`), каталог `0700`, файл
`0600`, атомарная запись, импорт из `~/.ssh/config` — из панели. Путь совпадает с апстримом,
поэтому уже настроенные хосты сохраняются.

Настройки плагина (включён/выключен, объявление агенту, шрифт терминала) — схема `Config`
в `src/index.ts`; она же служит страницей настроек этой строки профиля.

## Безопасность (читать до использования)

- **Пароли и парольные фразы хранятся в открытом виде** в `$DSH_HOME/dsh-ssh.json`. Это
  осознанная модель доверия: файл приватный, принадлежит пользователю. Не «шифруйте для
  галочки» и не отдавайте этот путь модели или логам.
- `ssh_upload` / `ssh_download` работают с локальной файловой системой **с правами процесса
  хоста** (не через песочницу). Маршруты `/api/dsh-ssh-rus/*` ограничены loopback, туннели
  слушают только `127.0.0.1`.
- `ProxyCommand` — shell-команда, выполняемая процессом хоста; берётся только из приватного
  файла пользователя. Агент видит лишь факт её наличия и не может создавать или изменять хосты.
- Вывод команд возвращается **как есть**: `env` на удалённой машине может вернуть секреты в
  историю чата. Передача и выполнение расходуют реальные ресурсы — подтверждайте перед запуском.
- Переподключение после обрыва может **повторить неидемпотентную команду** — учитывайте это в
  долгих операциях.

## Инструменты агента

`ssh_list`, `ssh_exec`, `ssh_upload`, `ssh_download`, `ssh_tunnel`, `ssh_cluster`. Агент видит
только те хосты, которые пользователь настроил в GUI или импортировал; выдумывать хосты ему
запрещено. Файлы и команды на локальной машине (там, где работает DSH) — только локальными
инструментами, `ssh_*` работают исключительно с удалёнными путями.

## Сборка и проверки

```sh
pnpm install
pnpm run typecheck   # пропущенный ключ локали — ошибка типизации
pnpm run build       # tsc (lib/types) + tsdown (lib/index.js, lib/client.js)
pnpm exec vitest run tests/locales-runtime.spec.ts
```

Проверено на DSH `0.2.0-rc.2`; `engines.dsh` — `>=0.1.7-rc.2`.
